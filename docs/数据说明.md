# 雨季遗址遮护的因果复盘与下一轮布点

本地数据与术语材料供业务人员整理分析资料使用，所有记录均为合成样例。

## 输入

`fixtures/` 包含 `primary.csv`, `support-1.csv`, `support-2.csv`。文件首行为字段名，空值表示来源没有给值。记录用于说明输入结构和实体关联，不含统计结论。

## 解释

有效范围、证据和审批状态按业务记录本身判断。不同表中的同一标识用于关联记录，不代表两份独立观察。资料存在未知、零和缺报的区别。

## 字段要点

`primary.csv`

- `wall` / `drain_group`：墙段与排水组。排水组内墙段共享外溢，不独立。
- `assigned`：抽签登记的意向组（`shelter`/`control`），复盘只按它比较。
- `sensor` / `calibration` / `model`：设备与逐行校准声明。若提供 `calibrations.csv`，以校准文件的"设备 × 型号 × 日期"覆盖为准。
- `observed_at` / `rain`：观察日期与连续降雨事件标识。同一 `rain` 内的观察是共同事件。
- `moisture` / `warning`：含水量与**该墙段材料**的警戒线。只有有效受雨观察时段才计入湿度结局。
- `damage_review`：表面病害记录。`unknown` 表示未确认，不能当作无损；独立复查请放 `damage_reviews.csv`。

`walls.csv`（或旧版 `support-1.csv`）

- `material` / `side`：材料与朝向，构成可推广条件。
- `emergency`：是否已达紧急病害线。为 `yes` 的墙段由保护人员立即干预，不进入下一轮对照。
- `neighbours`：相邻墙段，`|` 或 `;` 分隔；缺省时同排水组互相视为相邻。
- `sheltered` / `shelter_start` / `shelter_end`：实际遮护状态与日期，只用于解释遵从。`sheltered=no` 明确表示从未搭棚；两列都空表示未知。

`calibrations.csv`：`sensor, model, valid_from, valid_to, calibration`，校准只对声明日期与型号生效。

`damage_reviews.csv`：`review_id, wall, reviewed_at, outcome, independent`。同一 14 天窗口内的复查按一个簇处理。

`candidates.csv`：`wall, material, side, drain_group, available_from, available_to, neighbours, emergency, note`，用于下一轮布点。

`schedules.csv`：`schedule_id, wall, arm, start, end, status, signed_at, condition, comparison_snapshot, note`。`comparison_snapshot` 为 JSON，保存签署当时依赖的比较；`status` 为 `signed`/`confirmed` 的排期受保护，不因新报告自动挪动。
