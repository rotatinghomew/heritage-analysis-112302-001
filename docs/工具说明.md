# 遮护政策复盘与下一轮布点：使用说明

本工具回答两类问题，并为每次新观测保留可回查的比较：

1. **季中复盘**：按原抽签组评估"继续遮护"这一政策是否有支持；被遮墙与邻接墙的风险变化、不确定范围、可推广条件分别报告。
2. **下一轮布点**：从候选墙段与现有工期中找出能填补关键证据缺口的观察组合；被阻止的组合与剩余资源补不齐的缺口都要列出。

所有输入均为合成样例，不含真实遗址数据。

## 运行

```bash
python3 -m shelter_monitor review --fixtures fixtures            # 季中复盘（Markdown）
python3 -m shelter_monitor review --fixtures fixtures --format json --out report.json
python3 -m shelter_monitor plan   --fixtures fixtures            # 下一轮布点
python3 -m shelter_monitor audit  --fixtures fixtures            # 签排期审计
python3 -m shelter_monitor reopen --fixtures fixtures --previous old.json
python3 -m unittest discover -s tests                            # 测试
```

`examples/round2/` 是一个完整示例，包含独立复查、校准文件、候选墙段与已签排期。

## 输入文件

| 文件 | 必需 | 用途 |
| --- | --- | --- |
| `primary.csv` | 是 | 逐条含水量观察：墙、排水组、抽签组、设备、校准、日期、含水量、材料警戒线、降雨事件、表面病害 |
| `walls.csv` | 否 | 墙段静态字段：材料、方位、紧急线、相邻关系、是否/何时实际搭棚 |
| `support-1.csv` | 否 | 旧版墙段表（无 `walls.csv` 时使用），只含材料/方位/紧急线 |
| `support-2.csv` | 否 | 规程条目；可用 `neighbour_risk_margin` 给出邻墙风险界限 |
| `calibrations.csv` | 否 | 换机校准：设备、型号、有效起止日期、是否有效 |
| `damage_reviews.csv` | 否 | 独立病害复查：复查编号、墙、复查日期、结局、是否独立 |
| `candidates.csv` | 否 | 下一轮候选墙段与工期：材料、方位、排水组、可用起止、相邻、紧急线 |
| `schedules.csv` | 否 | 已签/已确认排期与签署时的比较快照 |

空值一律表示"来源未给值"，不会被当成 0 或"无棚"。要明确表示从未搭棚，请在 `walls.csv` 的 `sheltered` 列写 `no`。

### 相邻关系

`walls.csv` / `candidates.csv` 的 `neighbours` 列用 `|` 或 `;` 分隔，例如 `W2|W3`。没有提供时，同一排水组内的墙段被视为互相相邻——这是保守兜底，宁可在组内多算一次暴露，也不把邻墙当独立对照。

## 三条硬约束

### 1. 按抽签组评估，实际搭棚只解释遵从

`assigned` 列是抽签登记的意向组，复盘只按它比较。实际搭棚日期只进入"遵从"一栏，绝不重划实验组，也不产生 as-treated 比较。抽签为遮护但实际未搭的墙仍留在遮护臂，抽签为对照但邻墙被遮的墙仍留在对照臂，其邻墙暴露单独分析。

### 2. 同一场雨、同一排水组不是独立证据

- **同一场连续降雨 = 一个共同事件**。事件内多条墙段/多个时段的读数先按"墙 × 事件"折叠（该墙在该场雨内任一有效时段超警戒线即记 1），再按排水组汇总。
- **同一排水组共享外溢**，组内墙段不独立。事件内先按排水组求差，再对排水组等权平均。
- **只有同一事件、同一排水组内同时出现遮护与对照**，才构成一个可比簇。事件跨排水组的两臂对比会被显式排除，并列入 `cross_group_only_events`。
- **可比事件少于 2 个就不出区间**，报告状态为 `not_comparable`，而不是用读数条数把区间压窄。

因此 `clusters`/`comparable_clusters` 指"可比事件数"，不是观察条数。

### 3. 邻墙风险单独解释

邻墙暴露只在**对照意向墙**内比较：观察日有相邻墙处于实际遮护期者为暴露。若相邻关系或邻墙施工日期缺失，记为不确定（`neighbour_exposure` 中的单臂/无数据），不默认未暴露。这样遮护的直接效应与径流转移不会混在同一个系数里。

## 结局与证据缺口

- **湿度结局**：有效受雨观察时段内含水量是否超过该墙段材料警戒线（`warning` 列）。"有效"要求：校准有效、非设备重叠、有湿度与警戒线数值、有观察日期与降雨事件。
- **表面病害**：只计入独立复查窗口内的结果，同一 14 天窗口内的复查按一个簇处理；`unknown` 与无复查都记为缺口。
- **校准覆盖**：有 `calibrations.csv` 时，未被"设备 × 型号 × 日期"覆盖的读数一律记为 `calibration_uncovered`，不退回逐行声明；没有校准文件时才使用 `primary.csv` 的 `calibration` 列。
- **设备重叠**：同一设备同日被多墙共用 → 全部剔除；同一墙同设备同日的重复登记 → 保留首条、其余剔除。两种情况都列入 `device_overlaps`。
- **遵从缺口**：`sheltered` 与 `shelter_start` 都缺的墙记为 `actual_shelter_unknown`，不能当成"无棚"。

证据缺口清单里的墙**不会**出现在"干燥"或"无损"里，也不会被计为 0 风险。

## 结论等级

条件（按材料分组，方位作为同组内分层信息）的结论：

| 结论 | 含义 | 可否扩展 |
| --- | --- | --- |
| `extension_supported` | 直接收益上界 < 0，且邻墙风险上界 ≤ 规程界限，且至少 2 个可比事件 | 仅同类材料/朝向条件 |
| `benefit_supported_neighbour_unresolved` | 直接收益有支持，但邻墙风险未排除到界限内 | 否 |
| `not_supported` | 直接收益区间未完全低于 0 | 否 |
| `unknown_insufficient` | 无可用观察、单臂、可比事件不足，或同材料内两臂方位完全错开 | 否（缺样不等于安全） |

汇总结论为 `partial_extension_supported` 时，也只对列出的条件成立，不外推到其他材料或朝向。规程未给邻墙界限数值时，工具使用 0.05 的保守默认值，并在报告中标注"需业务确认"。

紧急线（`emergency=yes` 或独立复查为 `urgent`/`collapse`）的墙段：保护人员立即干预，**不得**为了补对照而放回无棚组。

## 下一轮布点

`plan` 的优先级：

1. 已签/已确认排期、紧急墙段不可挪动；
2. 只在同一排水组、同一工期窗内配对遮护与对照；
3. 相邻墙段的搭配若会污染对照或摧毁既有对照，列入 `alternatives_blocked` 并给出冲突类型；
4. 只补单臂的组合列入 `arm_extension_options`，明确不能单独补齐可比条件；
5. 剩余资源补不齐的缺口列入 `unfillable_gaps`，不记为"暂无风险"。

## 签排期审计与重开

- `audit` 并排列出每份已签/已确认排期的**签署时比较快照**与**当前比较**，两者共存；新证据不自动撤销排期。
- `reopen` 对比新旧报告：列出结论变化的材料条件（应重开的建议），以及受变化影响但仍受保护的排期、不受影响的排期。
- 签署快照里的旧条件键（如 `brick/north`）会先精确匹配、再退回材料键 `brick`，不会把不同材料混在一起。

## 每次收到新观测的操作顺序

1. 把新观察追加到 `primary.csv`（必要时补 `calibrations.csv`、`damage_reviews.csv`）。
2. 重跑 `review`，确认 `input_hash` 与 `event_coverage` 已更新。
3. 若结论等级或适用范围变化，先跑 `reopen --previous <上一版报告.json>`，再跑 `plan`。
4. 把 `review --format json --out` 的报告存档；下一轮 `reopen` 用它作为 `--previous`。
